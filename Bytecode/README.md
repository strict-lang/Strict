# Strict.Bytecode
Compiles Strict types into register based instructions, shared by the Strict VM (`Runtime`) and the native compiler (`Compiler`). `FileCompiler` compiles a file: `TypeCodegen` one type, `MethodCodegen`, `ValueCodegen` and friends the statements and expressions, `TestCodegen` the tests at the start of every method, `ConstantFolding` inlines constants, `LoopHoisting` reads a list member of a parameter or member (`map.values(index)`) once before a `for` instead of in every iteration, so GPU loops get it as a list, and computes arithmetic that does not change in a loop (`1000 / steps`, names, fields, `.Length` and literals only, never `outer`, judged by `Expressions/LoopNames` like the `strict check` loop rules) once before it as `let invariant<line>x<n>`, inner loops again inside the outer body. `LoopPeeling` (called by `LoopCodegen.Loop`) splits a loop over a count or a list whose body branches on `index is 0` or the last index (`Expressions/LoopEdge`) into a loop over that one element (`Range` or `Slice`, the branch true) and one over the rest (the branch false and folded away, `index` shifted only for a sliced list), so value, implicit members, outer and the collected result stay the same and the rest takes the branch free fast path. For native builds `StructLanes` splits values of small number types (2-4 Number members like `Complex`) into numbers: `Inliner(types, true)` inlines their methods without loops and early returns (also methods of the own type returning such a value, jump ids move to a range of their own), `from` writes a variable per member, member reads read it, parameters and members of such a type become one Number per member keeping their `Bits` (`LaneCalls`: `offset Complex` is `offset_real` and `offset_imaginary`, calls and constructors pass the numbers), and only a value leaving as a whole (returned, passed to a native, put into a list) is built again, so GPU kernels take them and CPU loops do not allocate them. `Linker` adds every used type with only the methods that are called (`Automatic` writes `Members` and `to HashCode` for a type when they are used), `BinaryFile` reads and writes the `.strictbinary` cache next to each file.

Numeric test comparisons use `Number.IsNearlyEqual` (relative tolerance `1e-5 * (1 + max(abs(actual), abs(expected)))`), numbers with a Step compare exactly after rounding, also in record fields and list elements of any depth (`Closeness`). A type that contains itself (a tree) is compared through its automatic `IsNearlyEqual(other)` (declared in Any, generated only when a test needs it), which recurses at runtime.

Bytecode format 7 binds compact method references to the owner's serialized length and CRC32. Loading checks the owner's source stamps, format, fingerprint and method-index bounds; stale references trigger recompilation.

`DataFiles` finds the test fixtures of a file from its decoded string literals for the VM and native test stamps. It skips `.git` and directories ignored by the repository's `.gitignore` (the rules are a dependency too), explicit existing file literals stay dependencies even when ignored. `python Bytecode/check_data.py` (also with `native`) checks it.
