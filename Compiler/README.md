# Strict.Compiler
Builds native executables: `NativeBuild` behind `strict build` turns the instructions of all used types into MLIR (`MlirModule`, one `MlirFunction` per method with `MlirStatements`, `MlirCalls`, `MlirLoops` and friends, `MlirKernel` and `MlirFastLoop` add a copy without per element checks to simple loops over lists, LLVM vectorizes it), adds the runtime written directly in MLIR (`NativeRuntime.mlir` for texts, lists, files, processes and the garbage collector, `NativeRuntimeWindows.mlir` or `NativeRuntimeLinux.mlir` for the platform) and runs mlir-opt, mlir-translate and clang (`Toolchain`, `ToolRunner`). mlir-opt first drops every private function nothing calls (`--symbol-dce`, the runtime helpers a program does not use), for the host and the GPU module alike: 420 test and example executables 26% smaller (FizzBuzz 387 to 224 KB, clang 2.1 to 1.0 s), the PTX of a small GPU program 132 to 6 KB (NearestNeighbors), `strict.exe` 3.67 to 3.55 MB, same speed.

A type of two 32 bit numbers (Vector2 `MlirPairs`, Size `MlirCouples`) is one 64-bit slot. A register holding a Vector2 that is read as a list (a `Numbers` parameter or return, a List method other than X, Y and Length, a loop, list arithmetic) becomes a list right after it is written, a list given or returned as a Vector2 becomes a pair (`MlirPacking`, the first such read decides), an index into a Vector2 reads the pair (`strict_two_at`). One-number types with `value.Bits is 32` (Degrees) are rounded to 32 bit when constructed, like on the Strict VM.

`Bootstrap.mlir` is the seed, the compiler compiled by itself: `Bootstrap.cmd` (Windows) and `bootstrap.sh` (Linux) build a first `strict` from it, which then builds itself. A native executable runs 1M loop iterations in 40 ms.
