# Strict.Runtime
The Strict VM: `strict <file>` and `strict test` run the instructions of `Bytecode` here without building an executable. `Execute` loads the types, `Resolver` numbers the locals and registers of every method into slots, resolves call targets and jumps and decodes constants, `Machine` calls methods and binds members and arguments, `Frame` runs one call in its own list of slots (a call of a method that only returns a member, like `Vector2.X`, reads it through `Accessor` without a call), `Looping`, `Operations` and `Storage` carry out the instructions, `Natives` the methods of the base types the VM implements itself.

Speed: 1M loop iterations take 105 ms (a native executable 40 ms), training `NeuralNetworks/Iris.strict` 2.4 s.


## Attention VM slowdown (2026-10-26)

The original `strict test NeuralNetworks/Attention.strict` reproduced the slowdown on merged dd537977. Source loading, linking and validation finished before the slow part. Tiny attention assertions took 1-8 ms, but the Stride prompt tests at lines 30-32 took 7.62, 34.06 and 39.26 s; the full file exceeded a 120 s limit. Attention runs on the CPU in the VM, through Attention.Scores/Softmax and ordinary bytecode instructions. It does not launch the native compiler, PTX tools or an external model runner. Prompt data comes from the local 286,304-byte blocks.gguf fixture. These timings do not establish that every reported 4-7 minute run has the same environment or duration.

Machine.Bound used a collecting loop. The compiler cost estimate includes expensive branches in Member/Argument and selected parallel execution from just 12 frame slots, even though most slots are temporary registers initialized to None. In an instrumented paired run, the first prompt assertion made 55,482 pool calls and 320 full collections, including 2.60 s collecting; keeping only frame initialization serial reduced these to 11 pool calls and four full collections (0.018 s collecting). The assertion fell from 5.81 to 0.36 s. These diagnostic binaries used the same -O2 pipeline and counters; they are separate from installed-build measurements. No logging or parallel rules were changed in production by the diagnostic.

Machine.Bound now fills its private slots with a local list accumulator, retaining members, defaults, arguments and the index slot. It avoids splitting each VM call into a pool job. `python Runtime/check_frames.py` reproduced the old frame-initialization budget failure before the change and now checks 10,000 distinct 32-slot frames within 20 ms (16.37 ms measured here). Installed strict.exe is 2,455,040 bytes, 2,048 bytes smaller than the preceding profiler build. Its unchanged original Attention tests pass in 29.20 s at eight threads: lines 30-32 take 0.396, 2.080 and 3.584 s; the first tiny assertion takes 0.34 ms. No Attention assertions or model thresholds were changed.

The remaining prompt cases still violate the editor's 20 ms budget. The serial-frame diagnostic of the full file executed 226.7 million VM instructions, entered 1.72 million methods, and allocated 146.7 million objects / 7.55 GB cumulatively; these are cumulative allocation counters, not resident memory or counts measured from the final list-accumulator implementation. Numbers still become four-field VmValue objects, lists hold boxed VmValue elements, and every multiply/add/index/loop step goes through Frame. Remaining work is a flat numeric representation and less per-instruction allocation/dispatch, plus explicit slow-suite classification and budget enforcement. Do not hide the prompt assertions or substitute native execution for the VM checks.

Machine, Frame and Operations passed VM/native tests; Constants passed VM tests, original Attention passed VM/native tests, Strict passed VM tests, and Runtime validation reports zero issues. Machine/Frame also passed with 24 threads. The full daily suite was not rerun. Ignored Compiler/output/AttentionAudit contains the bounded reproduction logs, instruction/allocator/GC counters and the serial-frame-only diagnostic; installed executables contain no audit instrumentation.
