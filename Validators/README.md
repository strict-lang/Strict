# Strict.Validators
The rules behind `strict check`: `Limits` (120 characters per indented line and 240 for a constant, 13 lines per method with header and tests, 18 methods (not for base types), 15 members, 40 constants, nesting depth 5, 10 times as much in a `Generated` folder and twice in a `Content` folder, members before methods: `MembersMustComeBeforeMethods`, `0 - x` where the 0 starts an operand must be written `-x`: `ZeroMinusMustBeNegation` (a leading minus applies to its first operand before `*`, `/`, `^` and `to`, so `0 - a ^ b` becomes `-(a ^ b)`), ...), `Names` (keywords, list prefixes, constant names, a loop whose only line is another loop names both iterators: `NestedLoopsMustNameIterators`), `UsageRules` and `TypeValidator` (unused or never changed variables and members), `MagicNumbers` (a number literal in a method body outside tests and constants other than one digit, 0.5, a power of ten or of two: `NumberMustBeNamedConstant`), `Duplicates` (a method body that already exists elsewhere: `MethodAlreadyExists`), `TestChecks` (`is true` in a test line: `IsTrueIsNotNeeded`), `SubstringLengths` (a Substring with a literal length 0 or 1: `SubstringLengthMustBeAtLeastTwo`, use index access `text(index)` or `""`), `Recursions` (a constant calling a method that uses the constant again, a method whose only line calls itself), `SureChecks` (an `is Error` check of a call whose body never returns Error, such as `PseudoRandom.Next`: `ErrorCheckCannotFail`), `LoopBodies` and `LoopBody` (a value that does not change in a loop: in an inner loop a branch on the first or last iteration `LoopEdgeMustBeOutsideLoop` or on such a value with a constant or return branch `LoopGuardMustBeOutsideLoop`, in a method under 10 lines a multiplication, division, remainder, power or longer computation `LoopInvariantMustBeOutsideLoop`; calls and members of types or numbers count as changing), `Writes` (in a type with native methods a method named Create, Delete, Change, Write, Save, Send, Close, ... with a result: `WriteMustReturnNothing`; the owning type or a handle type whose name ends in Handle may be returned), `Inlines` (a `let` used once, in the next line at the same indentation, whose inlined line still fits: `SingleUseLetMustBeInlined`; not when the value calls something and its use comes after `then`, `else`, `and`, `or` or another call, or a nested `for` rebinds `value` or `index`; `if condition`, `return a` and a last line `b` at the end of a method: `IfReturnMustBeThenElse`, write `condition then a else b`, not for a method without a result or with an `or` result type), `StatusCodes` (a method other than `Run` with a `Number` result that writes, a call line without a value, and returns an integer literal such as 0, 1 or -1 as a status, also in a `then` or `else` branch: `StatusNumberMustNotBeReturned`, return nothing, a Boolean, an Error or an enum), run by `ValidateCheck` for every file of a folder. Every issue prints as `<File>.strict:line <N>: <Rule>: <detail>`, `strict check <folder>` reports 0 issues before a commit.

`strict suggest <file> <method>` (`Suggestions`, `SuggestionCalls`, `SuggestionTests`) compiles candidate bodies for a method, links their combined dependencies once and keeps each body that passes the method's tests on fresh VM state, at most 32 candidates from the own, parameter and member types; a method name or its header line number selects an overload, `-` reads unsaved source from standard input. Passing tests never create a validation issue. `python Validators/verify-suggestions.py .` checks it end to end.
