# Strict.Validators
The rules behind `strict check`: `Limits` (120 characters per line, 13 lines per method with header and tests, 15 methods and members, ...), `Names` (keywords, list prefixes, constant names), `UsageRules` and `TypeValidator` (unused or never changed variables and members), `ConstantCollapser` (folds constant expressions), `Recursions` (a constant calling a method that uses the constant again, a method whose only line calls itself), run by `ValidateCheck` for every file of a folder. Every issue prints as `<File>.strict:line <N>: <Rule>: <detail>`, `strict check <folder>` reports 0 issues before a commit.

`strict suggest <file> <method>` (`Suggestions`, `SuggestionCalls`, `SuggestionTests`) compiles candidate bodies for a method, links their combined dependencies once and keeps each body that passes the method's tests on fresh VM state, at most 32 candidates from the own, parameter and member types; a method name or its header line number selects an overload, `-` reads unsaved source from standard input. Passing tests never create a validation issue. `python Validators/verify-suggestions.py .` checks it end to end.
