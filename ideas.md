# Ideas
Large features, difficult or long work and far fetched things, kept here until someone wants them. Not a to do list, lines may get deleted any time. Bugs go into `bugs.md`, speed work for soon into `performance.md`, while there are any.

## Features and long work
- Agent scratch runs, and only then agents drop Python for them (2026-11-14). A warm `strict serve` already holds the VM and the types, and native code that needs no linking and no GPU kernels is cheap, so a small program on top should be sub-millisecond and way faster than `python -c` on the same jobs (a file read, a numeric loop, a regex over text), not 10 ms against 100 ms. Missing first, taken from the 16 scripts agents wrote for the text-length work (`align`, `append`, `audit`, `emitter2`, `emitter_tests`, `fn`, `headers`, `helpers`, `lists`, `makers`, `makers2`, `makers3`, `readers`, `seal`, `twins`, `unseal`): `Text` regex with groups (every match, the captured pieces, a substitute, a whole-line match; the patterns are names, optional braces, escaped quotes and hex pairs). Read one file as one `Text` and write it back with the same `\n` or `\r\n` and no added blank line (`TextReader.ReadLines` and `TextWriter.Write` split and rejoin, which those scripts avoid with `newline=''`). Count of a piece of text, not one character (`text.count(anchor) == 1` before a replace; `Text.Count` counts a character). Repeat a text (`"\\00" * 17`). Root bytes, not `Compiler/MetalValue.Hex`: UTF-8 bytes of a text, a byte's value, a little-endian integer (`to_bytes`, `struct.pack('<qq')`), hex of one byte (`%02X`), and a scan of `\HH` escapes. The words after `strict run -c code` are the script arguments (`sys.argv` in every script). `strict run <Type>` and `strict run -c code` run on the VM, the default, and `-c` leaves no file behind. `strict <Type>` stays the native route. Already in the language, so not this work: `Split`, `Lines`, `Replace`, `IndexOf`, `StartsWith`, `EndsWith`, `Trim`, `Substring`, `is in`, `Directory.Files` with a pattern, `Path.FileName`, `Dictionary`. A Boolean line in a program is a test and does not run, so "exactly once" is an `Error`, not `is`. Measure every case against `python -c` before switching. Windows `cmd` and `.ps1` fail for rounds, `.py` less often and still often; Strict should fail less because code that does not build does not run, and a miss is cheap to retry. Until those features exist and the times hold, agents keep Python for throwaway glue.
- Faster LLM decoding on the RTX 4090 (2026-11-13): plain Qwen3.5-9B decoding spends 5.85 of 6.9 ms per token in products at about 900 GB/s, the rest are about 760 small kernels per token (norms, `DeltaBlock.Read`, quantizing the inputs) that a fusing GPU emitter could merge; MTP (5.5 ms per token, 2.67 of 3 drafts) would gain from tree drafts (runner-up tokens, a tree mask in attention, per branch DeltaNet states) and a DeltaNet replay with one thread per state column carrying its 128 numbers through the accepted tokens (0.5 ms per step), which a Strict loop can not express yet; the 4 token verify products read at 653 GB/s, 16 or 32 rows per block and longer chains were slower.
- Reusing results of unchanged calls: values are immutable and every result is consumed, so a call whose inputs (instance, arguments and what it reads) did not change since its last run can hand back the kept result instead of computing again, from `numbers.Sum` up to a pathfinding query on a big unchanged map. Needs purity per method (MlirPurity has a start), cheap change detection of the inputs (versions or hashes of lists instead of comparing them), a cache size limit and eviction, and only pays for expensive calls.
- A small page reused after a collection is cleared before its objects are handed out (strict_gc_small_page), also for texts the collector never reads: skipping it for texts made 20 million small texts 31.5 -> 29 ns each, but packed rows, gathered rows and other GPU blocks share the unscanned classes and may rely on zero padding; texts need classes of their own first.
- Two packages with a type of the same name in one executable (Left/Point and Right/Point): natively the symbols, register kinds and helpers use the short type name, a folder build stops with SameNamedTypes; qualify the symbols of a type whose short name is taken.
- On the web dead values can stay roots: Asyncify saves every local that is live at any unwind point of a function with whatever it held last, and the collector scans them (strict_registers_spilled). The old value of an owned local is freed when it is replaced (strict_rc_dead), so `moss = Loaded(model)` releases the old Moss; a value that is not provably owned (passed to a method returning it, aliased) can still be kept by such a copy until the local is reused. Precise roots (reference locals in a shadow stack frame the collector scans instead of the Asyncify locals) would cover all of them.
- Requests in threads of one server (the decided design, after several servers came first): a `for` runs in parallel when every effect of its body only touches resources the iteration owns (its accepted socket, its own output, files it creates), checked by MlirPurity; the pool takes jobs of several threads (one busy flag today, inner loops of a second request run serially); blocking natives (accept, receive, waiting for a process) count as stopped for collections; full collections inside long jobs; Process.FilesRead and claims per request. Served timeouts: a test over its time inside one long native call is reported but not counted, a gone caller is only noticed while VM work runs.
- OutOfMemory, crash reports and STRICT_ALLOC_PROFILE name the Strict methods on the stack on Windows and Linux; macOS uses the same unwinder calls (untested), strict_stack_starts on the web returns no frames yet.
- Nightly CI: build and run every program's Run once a day (games and long running apps for a few frames); work too slow for a Slow test (rebuilding all content, big models) belongs in a Run, not in tests.
- Networking: `Http.Send`, `Http.Started`/`Received` and `Hmac.Sha256` are in (Windows, Linux and the web checked, macOS untested), DeltaEngine's Google sign-in and sheet downloads use them: switch Rebalancing's `NativeIO.Http`/`Hmac` (with the user, it trades live); client certificates when a program needs them, TLS for multiplayer sockets later.
- f32 kernels: a GPU loop reading a `value.Bits is 32` member computes in f32 (WGSL on WebGPU, the 32 bit CUDA kernel natively); WGSL lacks Float8 `from` calls, Bytes results and rows.
- Release builds: platform builds into Release/<Platform> are optimized without debug checks, logging or per-call checks (the web runtime already is), plain `strict build`, test executables and the VM keep them; native needs a release flag on `strict build` for local benchmarks.
- Named iterators over counts (`for row, column in rows, width`) as one flat loop of rows * width with the names from the index (parallel, GPU kernel), then the `(index / n).Floor` and `index % n` loops of NeuralNetworks, Math/Matrix and the image decoders can name their iterators without losing their kernels.
- Cleanups shown by equivalent mutants, what is left after the redundant conditions were deleted (2026-11-12): f32 stores write the exact parts twice (MlirDeviceRows.Called, MlirDevice.Entry and MlirGrouped.Remembered call function.Store and then MlirExact.Set overwrites the same slots, a MlirDeviceRows fixture pins the doubled stores); MlirWholeNative line 135 passes the kind "c" where "i" is probably meant (both map to i64); the unguarded `instructions(writer < 0 then ... else writer)` selects in MlirWholeFlat 80, MlirWholeKernel 86, MlirWholeSpan 120 and MlirDestined.IsSafe; not looked at: Mentions.Unknown adding own constants, LoopPeeling.Folded `isChoice`, Specialization.Completed `method is not ""`, SpectralFit.Linear `coords.Length < 2`, the TypeInference fallbacks `2 - "a"` typed Number and `Mutable(a, b)` typed Mutable. Kept on purpose as shortcuts that skip real work: LoadReuse.Remapped/Source, MlirPacking.Kind/Repacked, MlirGrouped.Kept, MlirBiased.Biases, MlirGuards.IsSingle, Inliner.Inlinable, Mentions.Typed, ChangedArguments.Positions, ConstantMethods.Methods, the Floor special cases of MlirWholeFunction and MlirWholeCall.
- Many candidates in one request (Ben, 2026-11-18): one type with fixed tests and N alternative bodies for one method, sent over the server's connection from a native program, one result line per alternative. A trial's tests run in under 0.1 ms each, a call costs 170 to 450 ms around them (process, source search, compile and link), so 10,000 candidates need about 0.3 ms each: no process and no parsing of what did not change. Mutation runs are the nearest thing (every mutant one source edit, run alone).
- Later: Qwen3-Coder-Next 80B-A3B and Qwen3-Coder-30B with all experts, image blur on the GPU, Apple Silicon, AMD GPUs, batched training ideas.

## Model: Ternary Bonsai 27B
`C:/code/Models/Bonsai`, 12.7-18 ms per token on the RTX 4090 (Prism's llama.cpp ~11); per token (ncu) the products take ~8.7 ms, the quantize kernels ~0.6. Left:
- the dot products decode every PTQ1_0 block twice, the two lanes of a block should split the codes
- one kernel for 1 to 8 tokens (like Kindi's) so `LookupDecoding` verifies cheaper (2, 4, 8 tokens 27.7, 37.3, 47.2 ms against 16.8 for one)
- CPU loops unpack 3 bit rows to doubles (`MlirWidths` decodes only 4 and 6 bit blocks per use)
- the 257 `Sylvester` launches per token still take ~1.1 ms (4.4 us each with one barrier, latency bound): rotate the inputs of a block in fewer launches
- 10 GB budget: a holder process does not simulate it on Windows (the budget never saw the holder), capping the driver's free memory at 10 GB in `strict_gpu_free_memory` does (budget 8.5 GB, peak 10.0 GB in use, the same in cold and warm runs). Then 64 tokens decode in a median of 22-24 instead of 12-14 ms: per token 3-4 of the 12 CUDA graphs are instantiated anew (5 ms, 1 ms destroying, 9 instead of 12 updates), 3-4 cuMemAlloc/cuMemFree (2 ms), the result download waits 7 instead of 3 ms; 2 tokens per run take ~290 ms freeing and allocating ~100 buffers (one uploads 298 MB)
