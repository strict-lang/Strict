## Speed
Measured speed work, compiler front end first, then matrices, texts and the collector.
- Serial loops (below `MlirCost.Threshold`) run raw when they read lists at `index + offset` (parameters, members and checked local lists), calculate, use `and`/`or`/`xor` on Numbers and call pure Number methods that cannot fail (Examples/LoopSpeed and probes at 227 elements: offsets 23-27 -> 1.4-2.9 ns per element, local lists 45-65 -> 4-6, `xor` of two reads 25 -> 3, a `Twisted` call 31 -> 8.5, `MersenneTwister.Uints` 55 -> 32 ns per number at 10 million). Still generic (`strict_hoisted_read`/`strict_list_read`, `strict_is_failure`, `strict_list_push`): gathers `table(value)` 14-20 ns, calls that can fail or read lists (`MersenneTwister.Normals`), one thread of a parallel chunk (22 ns, its packed copies still read through `strict_hoisted_read`); a raw `Tempered` call stays at 31 ns, its f64 body has two remainders and no whole number version is used. Nothing reports a pure loop that stays generic.
- Appending in a loop (`Probe/AppendSpeed.strict`, 624 elements): `mutable raw = List(Number)`, then `raw = raw + value` costs 8.2 ns per element (`strict_list_add_owned`), a list seeded from a parameter or member (`mutable raw = start`) or from `List(Number) + first` 33 ns (`strict_list_add`, a new view per append): `MersenneTwister.Seeded` (240 ns per state, `Spread` has four remainders), `Uints` concatenates (`raw = raw + Generation(...)`). Treating `list + element` as fresh is not safe as long as its holder is shared with the left list: releasing the view must not free that holder. Next with the text work: a list that does not fit gets double the room (C# List), a raw collecting `for` writes its result at 1.4-2.9 ns per element.
- Every raw loop is emitted six times (one copy per packed format its lists may have at run time plus the plain one) next to its generic body: code size and lowering time grow with every loop that becomes raw, not measured yet (compare `strict build Strict.strict` and a NeuralNetworks program with the copies off).
- Lists of numbers made by generic list paths (`strict_list_add` growing `raw = raw + ...` in MersenneTwister.Uints, `strict_list_new` of other loops) are scanned by the collector: on wasm the halves of their numbers look like references and keep dead big lists alive while they live; they should be scanned only up to their items like `strict_numbers_new` lists.
- Realtime frames: a full collection at a frame end that takes longer than a few ms marks over several frame ends (incremental, the cards record what changed meanwhile).
- Texts carry their byte length and character length in front of their bytes since 2026-11-14 (plan.md, steps 1 to 3: Qwen tokenizer folder 0.28 -> 0.256 s, self-build 16.3 -> 15.5 s, `strict check Compiler` 26 -> 22.8 s). Next in plan.md: appending in a block with room (20000 appends up to 280000 characters take 207 ms, 74% of it the copy per append), substrings and lines as spans into their block, ASCII paths for indexing and iteration.
- Testing one file on the VM spends up to 1.6 s (Compiler/MlirCalls 1.6 s, MlirLibrary 1.3 s, Tokenizer 0.14 s), all of it again every run: TypeShape.MemberScope is rebuilt 1191 times and TypeCodegen.Generator 1239 times for Number.strict, Changes(lines).Members and .Methods per method body and call site, source discovery tokenizes every line with a `/`, ResolveCheck.Inference covers all project files. Compute shape scopes once per TypeCodegen, cache per file scopes in the server by file stamp.
- Short parallel loops: `Gpt2Block.Normalized` of one row of 768 numbers takes 37-61 us natively without GPU (85-138 before the pool cut the rest of a probed loop into pieces for its helpers only instead of about 500 pieces of one or two elements), one thread alone needs 37 us (48 ns per element in the generic body: memo check, two `index % size`, the `Scale` call), `Centered` 10-17 us. Left: the probe hands a loop over after 10 us although its rest takes less than the wake up, every piece starts with a memo miss (the row's `Squared` again), and the fork threshold (`MlirCost.Work` 50000, about 33 us of work) is below what a wake up costs on 128 threads.

## Features and long work
- Faster LLM decoding on the RTX 4090 (2026-11-13): plain Qwen3.5-9B decoding spends 5.85 of 6.9 ms per token in products at about 900 GB/s, the rest are about 760 small kernels per token (norms, `DeltaBlock.Read`, quantizing the inputs) that a fusing GPU emitter could merge; MTP (5.5 ms per token, 2.67 of 3 drafts) would gain from tree drafts (runner-up tokens, a tree mask in attention, per branch DeltaNet states) and a DeltaNet replay with one thread per state column carrying its 128 numbers through the accepted tokens (0.5 ms per step), which a Strict loop can not express yet; the 4 token verify products read at 653 GB/s, 16 or 32 rows per block and longer chains were slower.
- Reusing results of unchanged calls: values are immutable and every result is consumed, so a call whose inputs (instance, arguments and what it reads) did not change since its last run can hand back the kept result instead of computing again, from `numbers.Sum` up to a pathfinding query on a big unchanged map. Needs purity per method (MlirPurity has a start), cheap change detection of the inputs (versions or hashes of lists instead of comparing them), a cache size limit and eviction, and only pays for expensive calls.
- A one line edit of H3Video (StrictComfy) takes 6.5 s without kernel work: MLIR emission 2.4 s, of it 1.7 s emitting GPU kernels that then turn out unchanged, linking 1.4 s, GPU preparation 1.2 s, lowering 0.5 s. Skip emitting kernels when their types did not change. A change in any kernel rebuilds all of them (mlir-opt 7.6 s, PTX 8.8 s, cubins 12.7 s of 34 s). No cache per program: a shared cache of all programs would fit, 602 of the 722 functions of MossImage have the same text in H3Video, 3443 functions of 11 programs have 1652 distinct bodies. It needs kernels compiled one by one, and kernels will rarely change, so only worth it if updates hurt.
- Plain `strict test` mutates every passing file, about 110 ms per verified Ben candidate (309-330 instead of 200-209 ms); `unit` skips that but a cached unit run prints no per-test lines, which Ben counts: a mode for tool callers that always runs, prints every test and never mutates.
- A small page reused after a collection is cleared before its objects are handed out (strict_gc_small_page), also for texts the collector never reads: skipping it for texts made 20 million small texts 31.5 -> 29 ns each, but packed rows, gathered rows and other GPU blocks share the unscanned classes and may rely on zero padding; texts need classes of their own first.
- A strict build of Strict.strict makes about 168 million allocations (STRICT_ALLOC_PROFILE=1009 with STRICT_SERVER=0 at the start): TypeEntry.ShortName 10% (MlirFunction.TypeOf, TypeEntry.Wrapped, MlirKinds.MembersKind), LoadReuse.Reads 4.5% (RegisterCount, MlirPacking.Kind), Tokenizer.Tokens 4.2%, Text.Split 2.2%, TypeEntry.Unconstant 2% (Changing). Not time: all of MLIR emission is 3.4 of the 11 s of a build with no cached objects, none of these reaches 5 %.
- Two packages with a type of the same name in one executable (Left/Point and Right/Point): natively the symbols, register kinds and helpers use the short type name, a folder build stops with SameNamedTypes; qualify the symbols of a type whose short name is taken.
- On the web dead values can stay roots: Asyncify saves every local that is live at any unwind point of a function with whatever it held last, and the collector scans them (strict_registers_spilled). The old value of an owned local is freed when it is replaced (strict_rc_dead), so `moss = Loaded(model)` releases the old Moss; a value that is not provably owned (passed to a method returning it, aliased) can still be kept by such a copy until the local is reused. Precise roots (reference locals in a shadow stack frame the collector scans instead of the Asyncify locals) would cover all of them.
- Requests in threads of one server (the decided design, after several servers came first): a `for` runs in parallel when every effect of its body only touches resources the iteration owns (its accepted socket, its own output, files it creates), checked by MlirPurity; the pool takes jobs of several threads (one busy flag today, inner loops of a second request run serially); blocking natives (accept, receive, waiting for a process) count as stopped for collections; full collections inside long jobs; Process.FilesRead and claims per request. ## Performance
- Resident builds forward to the server but reuse nothing between requests except what the process already caches (a one line edit: Xor 1.04 -> 0.91 s, a big program 8.65 -> 8.5 s, no change 0.37 -> 0.03 s). What repeats per build of a big program: MLIR emission 1.45 s, splitting the module 0.8 s, link passes 0.9 s. Linker.Known does not help (it keys exact method lists, each link pass extends them) and skipping homes changes the output order, keep decoded homes or per function MLIR text instead, and compare with a server-less build (byte identical MLIR).

## Validator rules from the DeltaEngine review (2026-11-11)
All 440 DeltaEngine files were read for what `strict check` lets through (it reports 0 issues there). Most hits first, counts are DeltaEngine sites, each is a second way of writing the same thing:
- `ErrorMustNotBecomeAValue`: `x is Error then <number, true, false, value>` and `if x is Error` followed by `return <literal or value>`: the Error is swallowed and the frame goes on (`next.Drawn(screen) is Error then value else next` in every game Frame, `Cast(casters) is Error then 0 else ...`), about 90. The branch of an Error check should return that Error or another Error; leaving the check out already propagates it. StatusNumberMustNotBeReturned made 45 of these visible, the fix was always to drop the return type and the check.
- `ErrorCheckCannotFail` misses callees that turn every Error into a literal themselves: `current.Drawn(screen) is Error` where Drawn is Boolean and returns false on failure (Games/WebWars/WebWars.strict:61-72), ArenaHud.Draw, FractalPage.Published.
- StatusNumberMustNotBeReturned misses: `condition then 1 else 0` as the result (RealTimeStrategy/NetworkChecks.strict:18, ServerChecks.strict:30, about 30, also `(a then 1 else 0) + (b then 2 else 0)` bit sums), a literal after only tests (`Failures Number` ending in `0`, `10` or `7` in every *Checks type), `-1` or a huge constant for nothing found (about 10), and Number results only ever compared with `is 1` (Window.IsDebug, WebPage.Picture).
- `NumberStateMustBeEnum`: a Number member or parameter compared with `is <integer literal>` against two or more different literals in a type and never used in arithmetic (`page is 3`, `choice is 6`, `stage is 4`, `phase is 1`, `kind < 3`, `Gpu.State(3, 1)`, `NativeDraw.Quads(texture, 1, 0, ...)`), about 300. Types often define the constants (UnitCommand.MoveOrder, GhostMatch.Neutral) and then compare literals.
- `NumbersMustNotBeARecord`: one Numbers value indexed with three or more different integer literals in a method, or `x(index * N + k)` strides (`value(0)`..`value(8)` poses, `grade(8)`, `metrics(4)`), about 350; `ListIndexMustBeNamed` for handle lists (`images(9)`, `clips(7)`, `sounds(6 + kind)`), about 100. Both want a type with members.
- `TestMustCallItsOwnMethod`: a leading test line that does not mention the method it sits in (tests parked under a neighbour to get around the method length, about 170 lines), with `MethodWithBranchMustHaveTest` for the methods left without one (about 50).
- `MethodMustUseItsInstance`: a method that reads no member and no `value` but is called through a constant or a made up instance (`Boost.None.Cast(...)`, `PlayPage.Sample.Described`, `GameApplication(0, 0, 0, 0, "", false).Images`, `RaceTrack.Empty.Loaded`), about 70; the other way round `OwnTypeParameterMustBeInstanceMethod` (`Accepted(room Room)` in Multiplayer/Room.strict, 13).
- One way to build a list: `mutable list = List(T)` + `for` + `list = list + item` + `list`, `List(Mutable(T))` + `.Add`, and the plain `for` expression all occur, about 65 loops are pure maps or filters (`AccumulatingLoopMustBeForExpression`); `List(Number) + x` and `(x)` both build a one element list.
- `MixedAndOrMustBeParenthesized`: `and` and `or` at one depth, or an `is`/`<` operand of them without parentheses (`a is false or b is 0` parses differently than it reads), about 60 lines against several hundred parenthesized ones.
- `ConstantValueMustBeDefinedOnce`: the same constant name and value in several types of a package (tick step 0.0625 and `16` 25 times in RealTimeStrategy, Tiles 15, ImpactScale 0.6), a literal equal to an existing constant, the same text literal three times (`"Content.xml"` 6, `"Google sign-in failed, please try again"` 5).
- Hand written base methods: `a > b then a else b`, `x < low then low else ...`, `a + (b - a) * t`, `text.Substring(n, text.Length - n)`, `(x / 2 ^ n).Floor % 2 is 1`, `x < a or x > a`, `.Round(0)`, `2 ^ 0.5`, about 60 (needs Maximum, Clamp, Lerp, a substring to the end and a bit test to point to).
- `BooleanParameterMustNotSelectBehaviour` and Number parameters used as one (`test is 0`, `motion > 0`), about 45.
- `CopyConstructorMustBeUsed`: `Type(a, b, c, changed)` repeating own members where `Type(value, member = changed)` exists (12); `NamedArgumentMustDifferFromCurrent` (`mines = mines`); `MethodMustNotOnlyReturnMember` (12); `MemberMustBeReadSomewhere` for members only ever copied (Attack.managedExternally).
- `ConstructorCallMustNameArguments`: more than four positional literals or two bare `true`/`false`/`0` next to each other (`UnitCommand(k, id, v, 0, false)`, `Attack(2, 0, 0, 1, false, false)`, 12 argument SpecialAbilityState), about 120.
- `TestMustNotTouchFiles`: tests and constants that write or list real files (`ArenaProfile.Empty.Saved` writes Profiles/Player.profile on every run, `constant Loaded = ArenaReplays(Directory.Files(...))`), about 15; engine packages whose tests load game content (Graphics3D/Scenery.strict, Weapon.strict).
- `SameCallTwiceMustBeLet`: the token equal call with arguments twice in a method outside the tests (about 30).
- `Up to date` could also say whether the program is running: a pid stamp written by each running program (like `obj/strict.server*`) makes that a file read instead of a 0.55 s process query.
- `GarbageCollectionExceedsLimit` and `GarbageCollectionAboveTarget` could also name the largest allocating call sites of the window.
