# Game engine improvements
Details for the game engine (DeltaEngine) line of [improvements.md](improvements.md). Remove what is done, add new findings at the end, bugs go into improvements.md.

- iOS: `strict build <file> ios` stages an arm64 iOS 15 static archive with `strict_main` and the content; linking against the SDK, UIKit, window, input and audio, signing and TestFlight need the MacMini ([Compiler/IOS.md](Compiler/IOS.md)).
- Android release path for SoulCraft: `strict build <file> android` stages an API 26 arm64-v8a `libmain.so` and `assets/Content`; the APK/AAB, Activity/JNI glue, window, input, audio and ASTC/ETC2 textures belong to DeltaEngine. The link stops at the `stb_image.h` include paths of `Content/native/ImageFile.c` and `Graphics3D/native/Gpu.c` (no Android native flags yet); keep the shipped app's identity (package `de.mobilebits.soulcraftdefault`, its signing and saves).
- One game loop for all games: `Games/*`, `RealTimeStrategy/RtsGame.strict` and `Frameworks/GameApplication.strict` repeat the same `Played(application)` loop (21 times) because `current.Frame(handle, now)` returns the concrete game type. A `GameLoop` trait needs a type instance passed where a trait is expected, a method returning the trait type when the implementation returns its own type, and the loop keeping that value without knowing the concrete type.
- Networking for multiplayer: a small transport trait (a mock plus real sockets) and a lobby/match message layer shared by the real time strategy games; plan it here before implementing.
- Spine 2D skeletal animation for Elemental, TinyBat and other 2D games: wrap a native Spine runtime once, the `.strict` side only plays animations and sets skins.
- Platform services as trait implementations: Steam, Google Play Games and Apple Game Center implement the `Achievements`, `InAppPurchase` and login traits; a base login package (account id, name, avatar, sign in and out events) for all games.
