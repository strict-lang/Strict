# Improvements
In priority order. Remove what is done, add what is found, keep each item to what is still open (results go into the README of the package). Every item gets done before the bigger image processing and neural network examples, parallel loops and GPU (decided 2026-10-12).

1. **Neural networks** (the use case, results in `NeuralNetworks/README.md`): every training step still builds new lists for activations, deltas and weights (about 38% of 784-64-6 MNIST training is allocating and collecting), a call with loop-invariant arguments runs on every iteration natively (could be hoisted), loops with calls (`activation.Output(...)`, `Row(...)`) take the checked path. Next: bigger networks to measure parallel `for` on all cores, SIMD and the GPU against the C# version; swish (its derivative needs the weighted sums, which `Network` does not keep). Only small inline data, bigger samples get their own repository like `../Mnist`.
2. **Language models** (results in `NeuralNetworks/README.md`): the expert routing of the MoE models (Qwen3-Coder-30B-A3B), MXFP4 for gpt-oss, 32 bit sums for packed weights on the CPU and GPU (a decision: 16 bit weights accumulating in 32 bit), per row `Summed` still checks its lists and matrix rows are separate allocations. GPU (`Compiler/MlirGpu`, `MlirDevice*`, a launch costs about 130 us of driver time): math functions (exp, tanh, sqrt) and list methods (Sum, Length) on the device so layer norm, Gelu and softmax follow the matrix products, results that stay on the device until the CPU reads them, a `Range` loop on the device (its kernel started at 0), a conditional in a loop body keeps the loop serial (`MlirPurity`). Only F32 safetensors are read (`OnlyFloat32TensorsAreSupported`).
3. **DeltaEngine performance**: on the Strict VM `+`, `Lerp` and constructors are full calls (`Bound` fills every member slot, `Constructed` checks `IsStruct` by name every time), assigning a replacement or `position + offset` back to the same mutable variable could write in place, types made only of numbers (Vector2, Size, ColorValue) could be stored flat (a `List(Vector2)` as one array of doubles).
4. **Tooling**: not reported yet: a method whose tests a method of a used type passes (exactly one way), a returned value of the wrong type (`("a" + name)` in a `Texts` method becomes the characters of "ab"), an argument of the wrong type for a constructor (`MlirLines(value)` from an `InstructionEntry` ran on the VM and crashed natively), a dropped call result of a method that can never return an Error (dropped operators, literals and variables are `UnusedValueMustBeRemoved`). `strict suggest <file> <method>` in Strict for the VS Code client (all candidates verified in one process). For the client, in this order: several files or a folder in one native build (`strict test . lines`), `strict test <file> values` on the VM printing `Value <file>:line <n> hit <count> times[: <name> = <value>]` per executed line (values only for let/mutable/assignment/for lines when equal on every hit, Text cut after ~50 characters, lists as `<length>: first elements`, if branches counted; Frame and Machine are at 15 members, the VM loop must not slow down without it), later the Debug Adapter Protocol in the VM. Bytecode: copies of types from other packages and base types are still inlined into `.strictbinary` files (22% of WebWars, names differ by package), the `sources` entry repeats all paths (10 KB per file). A method that can never return an Error could skip the `CheckError` of its results (they made `strict.exe` 7% bigger, VM tests 10% slower). `strict_list_*_number` and `_text` in the runtime can go once the seed no longer calls them. The LanguageServer waits until after the parallel loops and GPU (decided 2026-10-13).
5. **Reflection** (only as use cases need it): `to Type` of a Text that is not a literal (needs type names at runtime), natively a `Variable` value is a `Generic` without its type, a `Stacktrace`'s `Method` is `Type.Method` text (a `Method` value needs the methods at runtime).

## Language and compiler
- **Same-named types in one build**: a build needing `WebWars/Scene` and `LogoApp/Scene` at once is not supported (types and native symbols are keyed by the plain name).
- **Stack overflows show no Strict stack** and the other tests of the file do not run (a depth counter in the VM needs room in `Frame` and `Machine`, both at 15 members and methods).
- **`Code` of a Dictionary natively** links nothing (Dictionary methods are runtime helpers), `got:` uses `to Text` for dictionaries; needs code converters for `strict_pairs_text`.

## Rebalancing: exact values and C# integration (../Rebalancing)
Decimals are done (README "Rules worth knowing", `Examples/Prices.strict`); still open: lists of stepped values (`has prices Numbers with Step 0.01`), `let`/`mutable` locals with a step. Libraries are done for Number, Text, Boolean, records of numbers as C structs and lists of numbers or records (`strict build X.strict library`, README "Command line"); next: lists of texts, Boolean record fields as C# bool instead of double, stepped values as exact int64 step counts instead of doubles, Strict calling C# host services, thread safety (one call at a time for now). Rebalancing now uses the generated C# binding and serializes calls in one host lock; policy coefficients cross as decimal text and scale selection returns an integer index. Reproduced 2026-10-16: C# decimal 12345678.12345678m -> double -> decimal becomes 12345678.1234568m (within 2^51 steps at Step 0.00000001). Required before porting order arithmetic: generated decimal bindings backed by exact step counts and scale metadata for scalar/record/list arguments and results; round-trip that value, 0.00846253 BTC and 82393.82 USDC unchanged, with explicit overflow outside the supported range. Acceptance: the ASP.NET host sends a candle/portfolio/settings snapshot, Strict returns proposed trades and reasons with decimal values unchanged, errors produce no orders, historical fixtures match the C# reference before its logic is removed.
