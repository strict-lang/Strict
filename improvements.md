# Improvements
In priority order. Remove what is done, add what is found.

1. **Dictionary generics**: `Dictionary(K, V)` works natively and on the Strict VM. It is built from type arguments or pairs, and its methods are runtime natives over the list of pairs (`Dictionary.strict` is the specification): Length, `in`, get (also `prices("apple")`), Add with DuplicateKey, Remove, and `is` between different type arguments. Still open: pairs whose key and value types differ (`Dictionary(Text, Number)`) compare and print natively as lists of one type; `for` over a dictionary gives the value type instead of the pair (`value.Key`, `value.Value`); generic types other than List and Dictionary are not instantiated.
2. **HashCode**: `HashCode(5)` builds the instance `HashCode(Number)`, compiled with Generic as Number, and `if generic is` cases naming a type are decided at compile time, so `HashCode.strict` passes on both backends. Still open: the hash itself is a placeholder (a number is its own hash, anything iterable hashes to its Length), Dictionary natives still scan all pairs. A real hash per type (number bits, text bytes, list elements, instance members) and a hash table in the Dictionary natives would make lookups constant time.
3. **Operator overloads by parameter type**: list `-`, `*`, `/` (with a list or a number), `3 + (4)`, Reverse, out of range indexes and the downcast Error work natively and on the Strict VM, `List.strict` passes on both. Both backends find methods with `TypeEntry.Callee` (name, argument count with defaults, and the return type for `to`). Two overloads with the same count still need the argument types in CallTarget and Callee and distinct native symbols: a type with `+(other Pair)` and `+(amount Number)` compiles both to one function `Pair_Plus_1` and its test executable hangs, the VM runs the first body for both. Indexing another type's constant list (`MlirLists.Steps(4)`) is unsupported natively.
4. **Errors instead of crashes**: the VM crashes are gone, failing tests print their value, but there is still no RuntimeError with a stack trace back to the `.strict` line.
   - A parse error (e.g. `number + + other` in a method body) crashes the same way (exit 139) instead of printing a ParsingFailed message with file and line.
   - Native `test` reports a missing test executable as `127 failed in Number.strict tool not found: Number.test.exe`. The exit code reads like a failure count and the line looks like a test summary.
5. **Output for VS Code**:
   - `run test`: print one line per test (passed or failed, with its line number and duration) and a total. Then the client no longer guesses passes from missing failure lines, and a crash no longer marks passed tests as failed.
   - Add a folder mode for `run test`: today every file starts its own process, which parses all files and infers all types again.
   - `check` prints automatic instance text `(UnusedMethodParameterMustBeRemoved, other, Never used)` instead of `ValidationIssue.to Text` (`UnusedMethodParameterMustBeRemoved: other`). Issues also need a line number: the client marks the first line containing the target for now. A folder outside root is printed with mixed separators (`C:/.../pkg\Unused.strict`).
6. **Native gaps**:
   - `to Type` is missing (`Variable.strict`, also on the Strict VM, which otherwise passes the same 217 files).
   - `Character("b").number` prints `b` instead of 98, the member load keeps the Character kind.
   - ImageProcessing executables crash when run (Image and ColorValue members).
7. **Validators**: a `let` with only constant values must be `constant`. The check misses list literals.
8. **Tooling**: LanguageServer in Strict (the C# one is on the `dotnet` branch), CI with the native toolchain.
9. **Strict VM speed**: 245 ms for 1M iterations, about 5x slower than native (45 ms). Fast enough for now. When needed, update frames and registers in place for values with only one reference.
10. **Mutable as signals** (design decision, from the 2023 blog post "mutable"): `mutable squareArea = length * length` would keep recomputing when `length` changes, while `constant` stays the first value. Today a `mutable` only changes when it is reassigned (README). Within one method the compiler could recompute the dependent mutables after each reassignment of their inputs; members would need dependency tracking across methods.
