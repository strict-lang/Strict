2. **Neural networks** (the use case): `NeuralNetworks/` has a multilayer perceptron written in Strict (see its README): `Layer` (fully connected, sigmoid, one weight row per neuron), `Network` (backpropagation over any number of layers, softmax with cross entropy for several outputs, momentum 0.5, weights start in plus minus 1 / square root of the inputs), `Csv` and `Dataset` (features scaled to 0..1, one-hot classes, every fifth sample held out, a new random order every epoch). Natively XOR (2-3-1) trains in 11 ms, Iris (4-8-3) in 25 ms with 97% test accuracy, Diabetes (19-10-2 on a quarter of the UCI Diabetic Retinopathy Debrecen data, 288 rows) in 80 ms with 60-64%. The MNIST digits moved into their own repository (github.com/strict-lang/Mnist, `../Mnist`): 256-32-4 neurons reach 100% on 32 held out 16x16 images in 0.49 s natively (58 s on the Strict VM), 784-64-6 neurons 68-82% on 28x28 images in 2.8 s. Every step still builds new lists for the activations, deltas and weights, and a method call with loop-invariant arguments runs on every iteration natively (the compiler could hoist it). A `for` over a list or a count whose body only loads variables, calculates numbers, reads lists at `index` and collects one value per element runs twice compiled (`Compiler/MlirKernel`, `MlirFastLoop`): when every list read at `index` is at least as long as the loop, a copy with an integer counter, direct loads and direct stores into the presized result runs (LLVM vectorizes it), otherwise the checked loop, where a too short list stops the method with the index Error. Measured 2026-10-14: an element-wise update of 784 numbers 3.15 to 0.75 ns per element, a dot product 1.12 to 0.35 ns, MNIST 256-32-4 0.48 to 0.12 s, 784-64-6 2.74 to 0.86 s, Iris 27 to 20 ms. Now about 38% of the 784-64-6 training is allocating and collecting (`strict_gc_allocate`, `next_span`, `memset`, mark): every step builds new weight rows, the previous weights are kept for the momentum and the ones before become garbage. Native code is built with `-march=native` and the add of a sum in such a loop (`sum = sum + ...`) may be reordered (README), so LLVM vectorizes sums (AVX2 with 4 or 16 partial sums). Loops with calls (`activation.Output(...)`, `Row(...)` per row) still take the checked path. On the Strict VM every number is a `VmValue` with four members, each arithmetic result allocates one. Next: bigger networks to measure parallel `for` on all CPU cores, SIMD, GPU and CUDA through MLIR, compared with the C# version. Data over 1 MB is downloaded when needed instead of being checked in. The old C# code in `C:\code\AiInvest\AiInvest.NeuralNetworks` is only a guide, it has bugs (MatrixNetwork backprop drops the hidden gradient, the Tanh, Swish and Logistic derivatives, CrossEntropy ignores the target). Long term a more abstract language uses Strict like DNA: long chains of simple instructions that are easy to copy, change, merge and test, which the higher level rewrites, tests and evolves to reach its goals.

4. **DeltaEngine performance** (measured 2026-10-14): natively 1224 sprites interpolating a `Vector2` and building their 13 instance numbers take 0.12 ms per frame (3.5 ms on the Strict VM), 1M `position = position + Vector2(0, 1)` 21.7 ms (1.3 µs each on the VM), 1M replacement constructors `Unit(unit, health = unit.health - 1)` 5.7 ms (1 µs on the VM), element writes into a 9216 number grid 1.1 ns each (225 ns on the VM, in place on both). Natively an allocation is cheap, the VM spends its time in calls. The VM reads members like `X` (`numbers.X`, `elements(0)`) without calls: `Runtime/Accessor` finds the member path of methods that only return a member or a constant element of one and `Frame` follows it, anything else (out of range, an Error) takes the normal call (sprites 2.6x faster than with three frames per `X`). Open: `+`, `Lerp` and constructors are still full calls on the VM (`Bound` fills every member slot, `Constructed` checks `IsStruct` by name every time), assigning a replacement or `position + offset` back to the same mutable variable could write the instance in place, types made only of numbers (Vector2, Size, ColorValue) could be stored flat (a `List(Vector2)` as one array of doubles).

## Language and compiler
- **Same-named types in one build**: a build needing `WebWars/Scene` and `LogoApp/Scene` at once is not supported (types and native symbols are keyed by the plain name).
- **Stack overflows show no Strict stack** and the other tests of the file do not run (a depth counter in the VM needs room in `Frame` and `Machine`, both at 15 members and methods).
- **`Code` of a Dictionary natively** links nothing (Dictionary methods are runtime helpers), `got:` uses `to Text` for dictionaries; needs code converters for `strict_pairs_text`.
- **`and`/`or` with a list operand is accepted**: `active >= 0 and (skills(active).name.StartsWith("Lance"))` is `Boolean and List` because `(x)` is a one-element list, the list (and its index -1) is built before `and`, the result is `(true)` on both backends (SoulCraft aborted natively with exit code 3). Operands of `and`, `or`, `xor` must be Booleans or Numbers, anything else should be a compile error naming the parentheses.
- **A constant named `Member` read through an instance is empty**: in a test of `Expressions/HiddenType`, `Counting.Member` (with `constant Member = SyntaxParser(...).Parse`) gave a node without children, `Member` alone worked (renamed to `Twiced`).
- **Package lookup misses ../Strict/Binary transitively**: a DeltaEngine/Physics3D type using Graphics3D/DeltaMesh (`has data BinaryData`) fails with `NameNotFound: BinaryData` until DeltaMesh declares `Binary/BinaryData`, SoulCraft resolves plain `BinaryData`.
- **Arc tangent of any number**: `Vector2(x, y).Atan` (atan2, degrees from +Y towards +X, `Vector2(1, 0).Atan is 90`) and `Ratio.Asin`, `Acos`, `Atan` are native on both backends, but `Ratio` is constrained to -1..1, so the arc tangent of a larger number needs `Vector2(value, 1).Atan`; the `Degrees(0)` body of `Vector2.Atan` is only the spec placeholder.
- A native runtime abort (index out of range) in a windowed exe exits with code 3 and prints nothing; print the error and Strict stack to stderr or a crash log next to the exe.

## Rebalancing: exact values and C# integration (../Rebalancing)
Stepped decimals (README "Rules worth knowing", `Examples/Prices.strict`) keep 12345678.12345678 at Step 0.00000001 and values up to 2^51 steps exactly (the rounding tolerance was over half a step above 2^49 steps), libraries for Number, Text, Boolean, records of numbers as C structs and lists of numbers or records (`strict build X.strict library`, README "Command line"); Rebalancing uses the generated C# binding behind one host lock, policy coefficients cross as decimal text. A stepped Number parameter or result is `decimal` in the generated C# (C# rounds an argument to its step and rounding mode like a Strict caller does, a result to whole steps, outside 2^51 steps the call throws an OverflowException `DecimalOverflow`). Still open: stepped record fields and lists as decimal, exact int64 step counts instead of doubles (needed for anything beyond 2^51 steps). Then: lists of stepped values (`has prices Numbers with Step 0.01`), `let`/`mutable` locals with a step, lists of texts, Boolean record fields as C# bool, Strict calling C# host services. Acceptance: the ASP.NET host sends a candle/portfolio/settings snapshot, Strict returns proposed trades and reasons with decimal values unchanged, errors produce no orders, historical fixtures match the C# reference before its logic is removed.
