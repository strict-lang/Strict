# Improvements
In priority order. Remove what is done, add what is found. Every item gets done before the bigger image processing and neural network examples, parallel loops and GPU (decided 2026-10-12).

1. **Neural networks** (the use case): `NeuralNetworks/` has a multilayer perceptron (`Layer` fully connected with sigmoid and one weight row per neuron, `Network` with backpropagation over any number of layers) `Xor.strict` learns XOR with 2-3-1 neurons in 20000 steps, `Csv` reads a CSV (a header line, the class in the last column) and scales every feature to 0..1, `Dataset.Images` reads PNG images from one folder per class, both one-hot encode the class and keep every fifth sample for testing: `Iris.strict` reaches 97% test accuracy with 4-8-3 neurons after 200 epochs, `Diabetes.strict` 72% on `diabetes.csv` (UCI Diabetic Retinopathy Debrecen, 1151 rows, 19 features) with 19-10-2 neurons after 200 epochs. They log their training time measured with `Process.Elapsed` (seconds since the process started): Xor trains in 7 ms natively (Strict VM 1.5 s), Iris in 17 ms (VM 4.4 s), Diabetes in 240 ms (was 670 ms: `%` of whole numbers uses integer remainder instead of `fmod`, for-expression results grow their list in place instead of allocating a view per element and start with the capacity of the loop, a loop over a list reads its items directly, a list parameter the method never changes is read through its items pointer fetched when the method starts, `Layer` keeps one weight row per neuron instead of dividing the weight index), that is 1.3 µs per sample for 210 weights, every step still builds new lists for the activations, deltas and weights. A method call with loop-invariant arguments runs on every iteration natively, the compiler could hoist it. `Digits.strict` classifies the 16x16 handwritten digits 0 to 3 of AiInvest (160 PNG images in `mnist/`, read with `ImageProcessing/Png` and `Compression/Inflate`): 100% test accuracy on the 32 held out images with 256-32-4 neurons after 100 epochs in 0.38 s natively (1.5 s before the result lists started with the loop's capacity and the rows), 3.3 ns per weight and sample for the forward and backward pass. The output layer is a softmax for several outputs (sigmoid for one) trained with cross entropy (output delta is output minus target), weights move with momentum 0.5 (heavy ball: the previous weights are the old list, one pass per row like plain gradient descent): Iris 22 ms, Diabetes 0.30 s, Digits 0.47 s with the same accuracy (Digits reaches it after 20 epochs already), XOR error 2.5e-5. Weights start in plus minus 1 / square root of the inputs and every epoch visits the samples in a new random order (`Dataset.Shuffled`, before all samples of one class came in a row): `Digits28.strict` learns the 28x28 JPG digits 4 to 9 of AiInvest (280 images in `mnist28/`) with 784-64-6 neurons, 82-88% test accuracy after 50 epochs in 2.6 s natively. Next: bigger networks to measure parallel speedups. The neural network is written in Strict, the old C# code in `C:\code\AiInvest\AiInvest.NeuralNetworks` (and the `AiInvest.NeuralNetworks.*` folders next to it) is only a guide, it has bugs (MatrixNetwork backprop drops the hidden gradient, the Tanh, Swish and Logistic derivatives, CrossEntropy ignores the target). Steps: XOR (`AiInvest.NeuralNetworks.Tests\LogicTests.cs`), a simple MNIST investigation (the digit images in `AiInvest.NeuralNetworks.Tests\Optimized16x16`, `SimpleMnistTraining` uses 256-64-1), then the usual samples (`iris.csv` and `diabetes.csv` in `AiInvest.Classifiers.RandomForest.Tests`), then bigger projects built on that. Number has `Exponential`, `Logarithm`, `SquareRoot`, `Random` (uniform below the value, seeded per run), `IsFinite`, `Round(decimals)`, bitwise `and`/`or`/`xor` and the constants `E`, `Pi`, `Phi`, lists have `Sum`, `Maximum` and `Minimum`. The goal is to find the performance bottlenecks and measure how much parallel `for` on all CPU cores, SIMD, GPU and CUDA through MLIR speed it up, compared with the C# version. Long term a more abstract language uses Strict like DNA: long chains of simple instructions that are easy to copy, change, merge and test, which the higher level rewrites, tests and evolves to reach its goals (trying different things, using what LLMs and other projects do).
2. **Tooling**: `.github/workflows/ci.yml` bootstraps from the seed on Linux with the LLVM 22 release archive, self builds until the fixpoint and runs every test on the Strict VM and natively (validated in a fresh WSL clone). A Windows job builds the same way with `mlir-opt` and `mlir-translate` from MSYS2 and clang from the LLVM 22.1.0 release (validated with a fresh clone and the local tools). The LanguageServer in Strict (the C# one is on the `dotnet` branch) waits until after the parallel loops and GPU (decided 2026-10-13, it needs console input and a JSON package), the VS Code client calls `strict` meanwhile.
3. **Reflection** (later, only as use cases need it): `"Number" to Type` builds `Type("Number", "Strict")`, `5 to Type` (any other value) is its static type and `value is Number` is decided at compile time from the static type, on both backends. `value.Members` lists the stored members of an instance as `Variable`s (name, static type, value) and `HashCode` of an instance combines the hashes of its members: the compiler writes `Members` and `to HashCode` for every type that uses them (`Bytecode/Automatic`). Not supported yet: `to Type` of a Text that is not a literal (needs the type names at runtime), natively the value of such a `Variable` is a `Generic` without its type, it can not be printed or compared yet, the `Method` of a `Stacktrace` is its `Type.Method` text on both backends (a `Method` value needs the methods at runtime).
