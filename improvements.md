# Improvements
In priority order. Remove what is done, add what is found. Every item gets done before the bigger image processing and neural network examples, parallel loops and GPU (decided 2026-10-12).

1. **Neural networks** (the use case): `NeuralNetworks/` has a multilayer perceptron written in Strict (see its README): `Layer` (fully connected, sigmoid, one weight row per neuron), `Network` (backpropagation over any number of layers, softmax with cross entropy for several outputs, momentum 0.5, weights start in plus minus 1 / square root of the inputs), `Csv` and `Dataset` (features scaled to 0..1, one-hot classes, every fifth sample held out, a new random order every epoch). Natively XOR (2-3-1) trains in 11 ms, Iris (4-8-3) in 25 ms with 97% test accuracy, Diabetes (19-10-2 on a quarter of the UCI Diabetic Retinopathy Debrecen data, 288 rows) in 80 ms with 60-64%. The MNIST digits moved into their own repository (github.com/strict-lang/Mnist, `../Mnist`): 256-32-4 neurons reach 100% on 32 held out 16x16 images in 0.49 s natively (58 s on the Strict VM), 784-64-6 neurons 68-82% on 28x28 images in 2.8 s. Every step still builds new lists for the activations, deltas and weights, and a method call with loop-invariant arguments runs on every iteration natively (the compiler could hoist it). Natively 60% of the 784-64-6 training is the weight update (`Layer.Moved` and `Row`, about 2.9 ns per weight, 10 cycles where C needs 3 and SIMD less than 1) and 13% the collector: every element read in a `for` body checks its bounds and the list version (`strict_hoisted_read`) and every result element goes through `strict_list_push`, which keeps LLVM from vectorizing. Rows are already contiguous doubles natively: one flat weight list with row and column computed from the index was 1.7x slower (4.65 s instead of 2.74 s, measured 2026-10-14), so the next step is checking lengths once before such a loop and writing results into the preallocated list, not a different matrix storage. On the Strict VM every number is a `VmValue` with four members, each arithmetic result allocates one. Next: bigger networks to measure parallel `for` on all CPU cores, SIMD, GPU and CUDA through MLIR, compared with the C# version. Data over 1 MB is downloaded when needed instead of being checked in. The old C# code in `C:\code\AiInvest\AiInvest.NeuralNetworks` is only a guide, it has bugs (MatrixNetwork backprop drops the hidden gradient, the Tanh, Swish and Logistic derivatives, CrossEntropy ignores the target). Long term a more abstract language uses Strict like DNA: long chains of simple instructions that are easy to copy, change, merge and test, which the higher level rewrites, tests and evolves to reach its goals.
2. **Evolutionary algorithms and more neural networks** (asked 2026-10-13): `NeuralNetworks/Weasel.strict` evolves a random text into "METHINKS IT IS LIKE A WEASEL" by mutation and selection (45-95 generations of 100 children, 2-5 ms natively), `Neuroevolution.strict` evolves the weights of the 2-3-1 XOR network instead of backpropagating them (tournament selection, uniform mutation, the best network survives: error 1e-13 after 300 generations of 50 networks in 46 ms). `LogicGates.strict` learns Or, And, Nor and Nand with single neurons (`Perceptron`, from AiInvest's LogicTests) and builds Xor from three, `Optimizer` adds Adam and RMSprop (`OptimizerComparison.strict`: below 0.01 XOR error after 2000 steps where momentum is still at 1), `Recurrent` with `BinaryAddition.strict` learns to add 7 bit numbers (100 of 100 new sums after 10000 examples in 0.29 s), `MachineLearning/` has k-means, k nearest neighbors, Gaussian naive Bayes, a Gini decision tree, a random forest (Iris: 88.7% cluster purity, 96.7% test accuracy for each classifier) and an order 5 Markov chain over downloaded Shakespeare, `ArmEvolution.strict` evolves the joint angles of an `Arm` (modified Denavit-Hartenberg rows) to a target, the 7 joints of a Franka Panda within 0.2-1.1 mm in 136 ms natively (the AiInvest version only added up angles), `LinearRegression.strict` reaches the least squares line by gradient descent, `Activation` adds Tanh, Relu, LeakyRelu and Softplus with correct derivatives (`ActivationComparison.strict` on Iris: all 97-100% except plain Relu). Next, simplest first, from AiInvest (`X:\AiInvest`, deleted projects are in its history) and BrightWire (github.com/jdermody/brightwire, 18 samples in `ExampleCode/Program.cs`, `ReberPrediction.strict` with a GRU learns the embedded Reber grammar where an Elman network stays at chance): swish (its derivative needs the weighted sums, which `Network` does not keep: recomputing them costs another matrix product per layer in every step, AiInvest's Tanh, Logistic and Swish derivatives and its CrossEntropy are wrong). Only small inline data, bigger samples get their own repository like Mnist.
3. **DeltaEngine performance** (measured 2026-10-14): natively 1224 sprites interpolating a `Vector2` and building their 13 instance numbers take 0.12 ms per frame (3.5 ms on the Strict VM), 1M `position = position + Vector2(0, 1)` 21.7 ms (1.3 µs each on the VM), 1M replacement constructors `Unit(unit, health = unit.health - 1)` 5.7 ms (1 µs on the VM), element writes into a 9216 number grid 1.1 ns each (225 ns on the VM, in place on both). Natively an allocation is cheap, the VM spends its time in calls. The VM reads members like `X` (`numbers.X`, `elements(0)`) without calls: `Runtime/Accessor` finds the member path of methods that only return a member or a constant element of one and `Frame` follows it, anything else (out of range, an Error) takes the normal call (sprites 2.6x faster than with three frames per `X`). Open: `+`, `Lerp` and constructors are still full calls on the VM (`Bound` fills every member slot, `Constructed` checks `IsStruct` by name every time), assigning a replacement or `position + offset` back to the same mutable variable could write the instance in place, types made only of numbers (Vector2, Size, ColorValue) could be stored flat (a `List(Vector2)` as one array of doubles).
4. **Tooling**: `.github/workflows/ci.yml` bootstraps from the seed on Linux with the LLVM 22 release archive, self builds until the fixpoint and runs every test on the Strict VM and natively (validated in a fresh WSL clone). A Windows job builds the same way with `mlir-opt` and `mlir-translate` from MSYS2 and clang from the LLVM 22.1.0 release (validated with a fresh clone and the local tools). The LanguageServer in Strict (the C# one is on the `dotnet` branch) waits until after the parallel loops and GPU (decided 2026-10-13, it needs console input and a JSON package), the VS Code client calls `strict` meanwhile: it reads the method headers itself for completion, hover, go to definition and signature help, suggests implementations from the tests of a method and reports methods that already exist (`MethodAlreadyExists`), both by running `strict test` on a temporary copy per candidate call (40 ms each). `strict check` reports a method whose implementation (without its tests, at least 40 characters, not calling methods of its own type) copies another method of the folder or the base types as `MethodAlreadyExists`, a method whose tests a method of a type it uses passes is not found yet (exactly one way to solve each problem). Also not reported yet: an argument of the wrong type for a constructor (`MlirLines(value)` inside a `for` over instructions built an `MlirLines` from an `InstructionEntry`, the VM ran it, natively it crashed). `1e-5` is three tokens (`1e`, `-`, `5`), only exponents without a sign like `1.99e9` are number literals. Later the search for implementations belongs into Strict too (`strict suggest <file> <method>` with real type inference, all candidates verified in one process instead of one each). `strict test <file> lines` builds the tests natively with a counter per source line (`Compiler/MlirLines`) and prints `Line <file>:<n> executed N times in X ms (self Y ms)` for every line of the compiled methods and of the untested methods of the file (0 times), X includes the callees (recursion counts twice), Y does not. For the VS Code client, in this order: several files or a folder in one native build (`strict test . lines`, one build per file takes minutes for a folder); a trace of one test printing the value of every implementation line (shown inline), later the Debug Adapter Protocol in the VM (breakpoints by line, stepping, frames and variables from the `Frame` slots). A method named like a type hides the type in its file: `AdjustBrightness.Process` makes the test runner's `Process.Elapsed` call the method, the VM logs `Unsupported native call Strict/ImageProcessing/Image.Elapsed` and every test of the file prints `(() ms)` (`strict check` should report such a method or the runner should name `Strict/Process`).
5. **Reflection** (later, only as use cases need it): `"Number" to Type` builds `Type("Number", "Strict")`, `5 to Type` (any other value) is its static type and `value is Number` is decided at compile time from the static type, on both backends. `value.Members` lists the stored members of an instance as `Variable`s (name, static type, value) and `HashCode` of an instance combines the hashes of its members: the compiler writes `Members` and `to HashCode` for every type that uses them (`Bytecode/Automatic`). Not supported yet: `to Type` of a Text that is not a literal (needs the type names at runtime), natively the value of such a `Variable` is a `Generic` without its type, it can not be printed or compared yet, the `Method` of a `Stacktrace` is its `Type.Method` text on both backends (a `Method` value needs the methods at runtime).
## DeltaEngine native packages (2026-10-13, blocking phases 3–5 and 9)

Done: a type without members whose methods have no body is implemented in C in
`native/` next to it (`Examples/NativeAdd`: `Adder.Add(1, 2)` calls `double Adder_Add(double self,
double left, double right)` from `native/Adder.c`). `strict build` links the C files (MlirForeign,
NativeSources, Windows with clang, Linux through WSL gcc, `native/<Platform>.flags`), the VM builds
`native/<Folder>.dll` (`.so` on Linux) when a source, `Compiler/strict.h` or the flags are newer and
calls it through the new root type `Library` (LoadLibraryA/GetProcAddress or dlopen/dlsym, 1 to 5
numbers, Errors for a missing library or symbol). Text and Numbers arguments and results and
`strict_fail` Errors work on both (strict.h, `NativeAdd` tests all of them, also in WSL), packages
copied from a clone or GitHub keep `native/`, the dotnet-era `NativePlugins/` is gone. CI runs
`Examples/NativeAdd` on both jobs (the Windows job extracts clang's headers too, the Linux steps are
validated in a fresh WSL clone, the Windows job is not run yet). A type with one member holds a handle: its bodyless
`from(...)` is the C constructor and its methods get the member as self (`Examples/NativeAdd/Counter`), so DeltaEngine can
write `let window = Window(1280, 720, "WebWars", false)` and `window.IsOpen` (Frameworks still pass handles).

Required acceptance checks:
- Examples/NativeAdd: bodyless Adder.Add(left Number, right Number) Number, implemented
  by native/Adder.c exporting double Adder_Add(double self, double left, double right).
  NativeAdd.Run asserts Adder.Add(1, 2) is 3 on VM and compiled Windows/Linux.
- Discover native/ sources and platform flags; compile/load DLLs for VM and link C
  sources for native builds. Fail visibly on compiler, linker, missing-library and
  missing-symbol errors. Rebuild when source/header/flags timestamps change.
- Compiler/strict.h supplies borrowed text/flat-number input and copied output, integer
  handles, STRICT_EXPORT and tagged strict_fail. Test text, numbers and Error returns.
- No callbacks into Strict. LoadLibrary/GetProcAddress on Windows, dlopen/dlsym on Linux.
  Validate indirect calls for zero through four explicit double arguments plus self.
- Preserve native/ when packages are copied. Document flags/ABI and ignore native DLLs.
- Compiler changes require stage-two/stage-three fixpoint, bootstrap regeneration when
  necessary, and existing VM/native regression suite per AGENTS.md.

Until this lands, headless engine work can continue; graphical/audio phases and full
WebWars acceptance remain blocked. This request does not mark those phases complete.

## Member defaults (2026-10-14)

Literals, empty `List(...)` and `Dictionary(...)` and one-member types with literal arguments (`has start Vector2 = Vector2(0, 0)`) are member defaults on both backends (an empty Dictionary was `None` on the VM and 0 natively, which crashed the first copy). Any other call (`= Size(1, 2)`, `= Range(0, 5)`) is still dropped silently and the member gets the empty value of its type: it should be evaluated or be an error. A list of texts as a default (`has names Texts = ("a")`) does not build natively, mlir-opt reports the undefined global `@c<Type>_$Tests_0_0_0` (the constructor references the text constants but they are only emitted for loads in the method).
