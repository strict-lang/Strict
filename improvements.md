# Improvements
In priority order. Remove what is done, add what is found. Every item gets done before the bigger image processing and neural network examples, parallel loops and GPU (decided 2026-10-12).

1. **`.strictbinary` cache**: `strict <file>`, `test` and `build` write `Name.strictbinary` next to `Name.strict` once all its tests passed: a zip with a `sources` entry (format version, every source file the compiler read with its modification time) and one entry per used type (`TypeEntry.Bytes`, read back by `EntryDecoder`). While no source file has a different modification time the tests count as passed and its bytecode is used instead of compiling again (`strict test Strict.strict` 3.1 s, cached 0.07 s). A new `strict.exe` does not invalidate it: after compiler changes delete the `.strictbinary` files. A text literal in the tested file that names an existing file (`"ImageProcessing/4x4.png"`, `root + "/Compiler/NativeRuntime.mlir"`) is tracked the same way (`BinaryFile.Data`), a literal naming a data folder (relative, without `.strict` files, like `"NeuralNetworks/mnist"`) tracks every file below it. Still open: a path built only from other values (not a literal) is not tracked.
2. **Neural networks** (the use case): `NeuralNetworks/` has a multilayer perceptron (`Layer` fully connected with sigmoid and one weight row per neuron, `Network` with backpropagation over any number of layers) `Xor.strict` learns XOR with 2-3-1 neurons in 20000 steps, `Csv` reads a CSV (a header line, the class in the last column) and scales every feature to 0..1, `Dataset.Images` reads PNG images from one folder per class, both one-hot encode the class and keep every fifth sample for testing: `Iris.strict` reaches 97% test accuracy with 4-8-3 neurons after 200 epochs, `Diabetes.strict` 72% on `diabetes.csv` (UCI Diabetic Retinopathy Debrecen, 1151 rows, 19 features) with 19-10-2 neurons after 200 epochs. They log their training time measured with `Process.Elapsed` (seconds since the process started): Xor trains in 7 ms natively (Strict VM 1.5 s), Iris in 17 ms (VM 4.4 s), Diabetes in 240 ms (was 670 ms: `%` of whole numbers uses integer remainder instead of `fmod`, for-expression results grow their list in place instead of allocating a view per element and start with the capacity of the loop, a loop over a list reads its items directly, a list parameter the method never changes is read through its items pointer fetched when the method starts, `Layer` keeps one weight row per neuron instead of dividing the weight index), that is 1.3 µs per sample for 210 weights, every step still builds new lists for the activations, deltas and weights. A method call with loop-invariant arguments runs on every iteration natively, the compiler could hoist it. `Digits.strict` classifies the 16x16 handwritten digits 0 to 3 of AiInvest (160 PNG images in `mnist/`, read with `ImageProcessing/Png` and `Compression/Inflate`): 100% test accuracy on the 32 held out images with 256-32-4 neurons after 100 epochs in 0.38 s natively (1.5 s before the result lists started with the loop's capacity and the rows), 3.3 ns per weight and sample for the forward and backward pass. The output layer is a softmax for several outputs (sigmoid for one) trained with cross entropy (output delta is output minus target), weights move with momentum 0.5 (heavy ball: the previous weights are the old list, one pass per row like plain gradient descent): Iris 22 ms, Diabetes 0.30 s, Digits 0.47 s with the same accuracy (Digits reaches it after 20 epochs already), XOR error 2.5e-5. Weights start in plus minus 1 / square root of the inputs and every epoch visits the samples in a new random order (`Dataset.Shuffled`, before all samples of one class came in a row): `Digits28.strict` learns the 28x28 JPG digits 4 to 9 of AiInvest (280 images in `mnist28/`) with 784-64-6 neurons, 82-88% test accuracy after 50 epochs in 2.6 s natively. Next: bigger networks to measure parallel speedups. The neural network is written in Strict, the old C# code in `C:\code\AiInvest\AiInvest.NeuralNetworks` (and the `AiInvest.NeuralNetworks.*` folders next to it) is only a guide, it has bugs (MatrixNetwork backprop drops the hidden gradient, the Tanh, Swish and Logistic derivatives, CrossEntropy ignores the target). Steps: XOR (`AiInvest.NeuralNetworks.Tests\LogicTests.cs`), a simple MNIST investigation (the digit images in `AiInvest.NeuralNetworks.Tests\Optimized16x16`, `SimpleMnistTraining` uses 256-64-1), then the usual samples (`iris.csv` and `diabetes.csv` in `AiInvest.Classifiers.RandomForest.Tests`), then bigger projects built on that. Number has `Exponential`, `Logarithm`, `SquareRoot`, `Random` (uniform below the value, seeded per run), `IsFinite`, `Round(decimals)`, bitwise `and`/`or`/`xor` and the constants `E`, `Pi`, `Phi`, lists have `Sum`, `Maximum` and `Minimum`. The goal is to find the performance bottlenecks and measure how much parallel `for` on all CPU cores, SIMD, GPU and CUDA through MLIR speed it up, compared with the C# version. Long term a more abstract language uses Strict like DNA: long chains of simple instructions that are easy to copy, change, merge and test, which the higher level rewrites, tests and evolves to reach its goals (trying different things, using what LLMs and other projects do).
3. **Dictionary generics**: `Dictionary(K, V)` works natively and on the Strict VM. It is built from type arguments or pairs, and its methods are runtime natives over the list of pairs (`Dictionary.strict` is the specification): Length, `in`, get (also `prices("apple")`), Add with DuplicateKey, Remove, and `is` between different type arguments. `for` over a dictionary gives its pairs (`value.Key`, `value.Value`), typed `List(K, V)` when key and value types differ, and such pairs compare and print natively too. Natively pairs and dictionaries of any key and value types print and compare: `strict_pair_text`, `strict_pairs_text`, `strict_pair_equal` and `strict_pairs_equal` get the key and value converters or comparators as function arguments. Native lookups get the hash and equality of the key type as function arguments too, an instance key (`Dictionary((ColorValue(1, 0, 0), "red"))`) uses `strict_equal_ColorValue` and `strict_hash_ColorValue` (the hash of its text, like `HashCode`). Still open: natively generic types other than List and Dictionary are not instantiated, a type with `has first Generic` and `has second Generic` logs `ZzPair(1, 2)` as `((), ())` (the VM: `(1, 2)`) and compares Text members by pointer. The type arguments have to follow the constructor call (`ZzPair(Text, Number)` from the argument types in member order) into the kinds of field loads and method results, and the struct text and equality functions need them (like the pair converters as function arguments, or one instantiated type per use).
4. **Tooling**: LanguageServer in Strict (the C# one is on the `dotnet` branch), CI with the native toolchain.
5. **Reflection** (later, only as use cases need it): `"Number" to Type` builds `Type("Number", "Strict")` and `value is Number` is decided at compile time from the static type, on both backends. Not supported yet: `to Type` of other values (`Any.strict`, `5 to Type` would be the static type) and of a Text that is not a literal (needs the type names at runtime), the members of an instance (`HashCode` hashes an instance through its text, member wise would be faster), the `Method` of a `Stacktrace` is its `Type.Method` text on both backends (a `Method` value needs the methods at runtime).
6. **Strict VM speed**: 255 ms for 1M iterations, about 6x slower than native (40 ms), but numeric code with method calls and lists is far slower: training `NeuralNetworks/Xor.strict` takes 1.1 s against 7 ms natively, `Iris.strict` 3.9 s against 17 ms (in the morning of 2026-10-12: 3.5 s and 25 s with process start), `ProcessImage` of the 400x300 progressive `test_image.jpg` 82 s against 250 ms. Constant lists are built once natively, `Resolver` finds the target of every call once when the types are loaded, the native loop improvements (for-expression lists grown in place with the loop's capacity, items read directly) help the VM as well. An element write to a list that is used elsewhere too (`Frame.Replaced`, `Looping.Counted`) no longer copies it: `strict_list_write` writes in place and turns the old header into a record of the replaced value, hoisted item pointers compare a global write counter that LLVM moves out of loops which never write. The records point from older to newer versions, so a stale reference to an old version (conservative stack scan) kept every later record alive (Iris used 1 GB): a list whose items live in its first block gets its own items array on the first versioned write and a new array after max(64, capacity) versioned writes, which bounds what one stale reference keeps (Iris 15 MB). Locals are slots: `Resolver` numbers the locals of every method when the types are loaded (`#this`, `value`, `#result`, `#flag`, `#loop`, `index`, then members, parameters and variables) and writes the slot into the instructions, `Frame` keeps them in one list, no local is found by name anymore and a call builds its locals in one allocation: Iris trains in 3.9 s (5.5 s before). A collection marks everything still alive (the loaded bytecode, the data), after at least 16 MB instead of 4 MB that costs less: Iris trains in 3.7 s instead of 4.5 s (8 MB 4.0 s, 32 MB 3.8 s), 1M loop iterations use 22 MB instead of 9 MB, native programs are unaffected. Number constants are decoded once when the types are loaded and `true` and `false` are shared values (no measurable change). Profile of Iris: the collector about 25% and `Machine.Step` 10%, every step allocates a new `Frame` and every register or local write a 48 byte version record because the previous frame still points to the list. The VM's Dictionary natives still scan all pairs (`Natives.Keyed`, natively an open addressing index in the list holder: 20000 Adds and lookups in 85 ms). Next: the compiler updates a value in place when its previous version is never used again (`current = Step(current)`): an element write is versioned (`strict_list_write`, a 56 byte block per write) as soon as the list was passed to any method, even one that only reads it, an escape analysis of the callees (does a method store or return its parameter) would let the VM keep registers and locals in its loop and write them with `strict_list_set`, and native code would gain the same. Smaller: `Natives.TypeOf` by index instead of comparing type names (`Natives.Short` per field load, about 3%).
7. **`name = expression`** (decided 2026-10-12, from the 2023 blog post "mutable"): shorthand for a single-expression method with an inferred return type, locally and on types, parameters may have defaults. Every use reads the current values it depends on, assigning to the name is an error, `let` keeps a calculated value and `mutable` a reassignable one. Effectful expressions run on every use, caching is only allowed when it keeps that behavior. Only for very simple, obvious things (square root, length, sin, cos of local values), one expression is not a tested method:
   ```
   mutable position = 3
   next(add = 1) = position + add
   next is 4
   position = 10
   next is 11
   next(2) is 12
   ```
