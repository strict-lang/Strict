# Improvements
In priority order. Remove what is done, add what is found. Every item gets done before the bigger image processing and neural network examples, parallel loops and GPU (decided 2026-10-12).

1. **Neural networks** (the use case): `NeuralNetworks/` has a multilayer perceptron written in Strict (see its README): `Layer` (fully connected, sigmoid, one weight row per neuron), `Network` (backpropagation over any number of layers, softmax with cross entropy for several outputs, momentum 0.5, weights start in plus minus 1 / square root of the inputs), `Csv` and `Dataset` (features scaled to 0..1, one-hot classes, every fifth sample held out, a new random order every epoch). Natively XOR (2-3-1) trains in 11 ms, Iris (4-8-3) in 25 ms with 97% test accuracy, Diabetes (19-10-2 on a quarter of the UCI Diabetic Retinopathy Debrecen data, 288 rows) in 80 ms with 60-64%. The MNIST digits moved into their own repository (github.com/strict-lang/Mnist, `../Mnist`): 256-32-4 neurons reach 100% on 32 held out 16x16 images in 0.49 s natively (58 s on the Strict VM), 784-64-6 neurons 68-82% on 28x28 images in 2.8 s. Every step still builds new lists for the activations, deltas and weights, and a method call with loop-invariant arguments runs on every iteration natively (the compiler could hoist it). Next: bigger networks to measure parallel `for` on all CPU cores, SIMD, GPU and CUDA through MLIR, compared with the C# version. Data over 1 MB is downloaded when needed instead of being checked in. The old C# code in `C:\code\AiInvest\AiInvest.NeuralNetworks` is only a guide, it has bugs (MatrixNetwork backprop drops the hidden gradient, the Tanh, Swish and Logistic derivatives, CrossEntropy ignores the target). Long term a more abstract language uses Strict like DNA: long chains of simple instructions that are easy to copy, change, merge and test, which the higher level rewrites, tests and evolves to reach its goals.
2. **Evolutionary algorithms and more neural networks** (asked 2026-10-13): `NeuralNetworks/Weasel.strict` evolves a random text into "METHINKS IT IS LIKE A WEASEL" by mutation and selection (45-95 generations of 100 children, 2-5 ms natively), `Neuroevolution.strict` evolves the weights of the 2-3-1 XOR network instead of backpropagating them (tournament selection, uniform mutation, the best network survives: error 1e-13 after 300 generations of 50 networks in 46 ms). `LogicGates.strict` learns Or, And, Nor and Nand with single neurons (`Perceptron`, from AiInvest's LogicTests) and builds Xor from three, `Optimizer` adds Adam and RMSprop (`OptimizerComparison.strict`: below 0.01 XOR error after 2000 steps where momentum is still at 1), `Recurrent` with `BinaryAddition.strict` learns to add 7 bit numbers (100 of 100 new sums after 10000 examples in 0.29 s), `MachineLearning/` has k-means, k nearest neighbors, Gaussian naive Bayes, a Gini decision tree, a random forest (Iris: 88.7% cluster purity, 96.7% test accuracy for each classifier) and an order 5 Markov chain over downloaded Shakespeare, `LinearRegression.strict` reaches the least squares line by gradient descent, `Activation` adds Tanh, Relu, LeakyRelu and Softplus with correct derivatives (`ActivationComparison.strict` on Iris: all 97-100% except plain Relu). Next, simplest first, from AiInvest (`X:\AiInvest`, deleted projects are in its history) and BrightWire (github.com/jdermody/brightwire, 18 samples in `ExampleCode/Program.cs`): swish (its derivative needs the sums, AiInvest's Tanh, Logistic and Swish derivatives and its CrossEntropy are wrong), inverse kinematics for the 6 joints of the Franka arm (`RobotEvolution.cs`, `ArmEvolution.strict` does it for a planar arm with 2 links), then Reber grammar prediction with a GRU or LSTM. Only small inline data, bigger samples get their own repository like Mnist.
3. **Dictionary updates**: a `Dictionary` has no way to change the value of an existing key, `Add` fails with `DuplicateKey`, `table(key) = value` is not supported (`KeyNotFound` on the Strict VM, a segmentation fault natively) and `table.Remove(key).Add(key, table(key) + 1)` copies the whole dictionary on every update (the Markov chain over 200000 characters ran out of memory natively, it now searches the text instead). Counting words, histograms and caches need an in place update, e.g. `table(key) = value` adding or replacing the entry like list element writes (needs the user's ok, Dictionary is a root type).
4. **Tooling**: `.github/workflows/ci.yml` bootstraps from the seed on Linux with the LLVM 22 release archive, self builds until the fixpoint and runs every test on the Strict VM and natively (validated in a fresh WSL clone). A Windows job builds the same way with `mlir-opt` and `mlir-translate` from MSYS2 and clang from the LLVM 22.1.0 release (validated with a fresh clone and the local tools). The LanguageServer in Strict (the C# one is on the `dotnet` branch) waits until after the parallel loops and GPU (decided 2026-10-13, it needs console input and a JSON package), the VS Code client calls `strict` meanwhile: it reads the method headers itself for completion, hover, go to definition and signature help, suggests implementations from the tests of a method and reports methods that already exist (`MethodAlreadyExists`), both by running `strict test` on a temporary copy per candidate call (40 ms each). `strict check` reports a method whose implementation (without its tests, at least 40 characters, not calling methods of its own type) copies another method of the folder or the base types as `MethodAlreadyExists`, a method whose tests a method of a type it uses passes is not found yet (exactly one way to solve each problem). Later the search for implementations belongs into Strict too (`strict suggest <file> <method>` with real type inference, all candidates verified in one process instead of one each). Found by the client (build 11:59), all hit while typing a method test first, all should be errors with file and line: a line with only a tab inside or at the end of a method crashes `strict test` (exit 139 without output), an empty line between a test and the implementation drops the test (`All tests passed` without running it), a method with only tests exits 127 without output when its type has members (`ImplementationNotFound` only without members). `strict test <absolute path>` of a project file outside the Strict folder names the package of a sibling type after the path ("Unsupported native call Strict/C:/Users/.../Helper.Doubled", got 0), the same file given relative to the Strict folder passes. For the VS Code client, in this order: failed tests print no duration yet (`Test failed: ... (x ms)` like passed ones, the client takes the gap since the previous test line meanwhile); an option of `strict test` printing time and executions per line (`InstructionEntry.line`) or per method, or writing a `.cpuprofile`, to investigate the few slow tests (the client would show hot lines like NCrunch); executed lines with hit counts for VS Code's Test Coverage view (the client paints every line of a tested method as covered today); `strict format <file>` printing the canonical source (the client only fixes whitespace); a trace of one test printing the value of every implementation line (shown inline), later the Debug Adapter Protocol in the VM (breakpoints by line, stepping, frames and variables from the `Frame` slots).
5. **Reflection** (later, only as use cases need it): `"Number" to Type` builds `Type("Number", "Strict")`, `5 to Type` (any other value) is its static type and `value is Number` is decided at compile time from the static type, on both backends. `value.Members` lists the stored members of an instance as `Variable`s (name, static type, value) and `HashCode` of an instance combines the hashes of its members: the compiler writes `Members` and `to HashCode` for every type that uses them (`Bytecode/Automatic`). Not supported yet: `to Type` of a Text that is not a literal (needs the type names at runtime), natively the value of such a `Variable` is a `Generic` without its type, it can not be printed or compared yet, the `Method` of a `Stacktrace` is its `Type.Method` text on both backends (a `Method` value needs the methods at runtime).
