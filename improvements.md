# Improvements
In priority order. Remove what is done, add what is found.

1. **Dictionary generics**: `Dictionary(K, V)` works natively and on the Strict VM. It is built from type arguments or pairs, and its methods are runtime natives over the list of pairs (`Dictionary.strict` is the specification): Length, `in`, get (also `prices("apple")`), Add with DuplicateKey, Remove, and `is` between different type arguments. `for` over a dictionary gives its pairs (`value.Key`, `value.Value`), typed `List(K, V)` when key and value types differ, and such pairs compare and print natively too. Still open: natively only Text and Number keys and values compare and print (a pair with a Boolean or a struct value compares its slots as numbers); generic types other than List and Dictionary are not instantiated.
2. **HashCode**: `HashCode.strict` hashes a number to itself, texts and lists by combining their elements (times 31, modulo 2^32, `"abc"` is 96354), anything else through its text. Native Dictionary lookups use an open addressing index kept in the list holder, built on the first lookup and extended after appends (20000 Adds and lookups: 550 ms before, 85 ms now). Still open: the Strict VM's Dictionary natives still scan all pairs, and hashing an instance through its text is slow (a member wise hash needs reflection).
3. **Operator overloads by parameter type**: list `-`, `*`, `/` (with a list or a number), `3 + (4)`, Reverse, out of range indexes and the downcast Error work natively and on the Strict VM, `List.strict` passes on both. Overloads with the same argument count are chosen by the argument types (`Vector2 * Vector2` is the dot product, `Vector2 * 3` scales) on both backends. Still open: a method call overload (`a.Scaled(3)`) whose return type differs from the other overloads is typed with the last one (only operators use the chosen overload's return type), and an argument that only converts to the parameter type (Number to Byte, anything to Generic) falls back to the first overload with that count. Indexing another type's constant list (`MlirLists.Steps(4)`) is unsupported natively.
4. **Errors instead of crashes**: the VM crashes are gone, failing tests print their value, but there is still no RuntimeError with a stack trace back to the `.strict` line.
   - A parse error (e.g. `number + + other` in a method body) crashes the same way (exit 139) instead of printing a ParsingFailed message with file and line.
   - Native `test` reports a missing test executable as `127 failed in Number.strict tool not found: Number.test.exe`. The exit code reads like a failure count and the line looks like a test summary.
5. **Output for VS Code**:
   - `run test`: print one line per test (passed or failed, with its line number and duration) and a total. Then the client no longer guesses passes from missing failure lines, and a crash no longer marks passed tests as failed.
   - Add a folder mode for `run test`: today every file starts its own process, which parses all files and infers all types again.
   - `check` prints automatic instance text `(UnusedMethodParameterMustBeRemoved, other, Never used)` instead of `ValidationIssue.to Text` (`UnusedMethodParameterMustBeRemoved: other`). Issues also need a line number: the client marks the first line containing the target for now. A folder outside root is printed with mixed separators (`C:/.../pkg\Unused.strict`).
6. **Native gaps**:
   - `Character("b").number` prints `b` instead of 98, the member load keeps the Character kind.
   - ImageProcessing executables crash when run (Image and ColorValue members).
7. **Validators**: a `let` with only constant values must be `constant`. The check misses list literals.
8. **Tooling**: LanguageServer in Strict (the C# one is on the `dotnet` branch), CI with the native toolchain.
9. **Reflection** (later, only as use cases need it): `"Number" to Type` builds `Type("Number", "Strict")` and `value is Number` is decided at compile time from the static type, on both backends. Not supported yet: `to Type` of other values (`Any.strict`, `5 to Type` would be the static type) and of a Text that is not a literal (needs the type names at runtime).
10. **Strict VM speed**: 245 ms for 1M iterations, about 5x slower than native (45 ms). Fast enough for now. When needed, update frames and registers in place for values with only one reference.
11. **Mutable as signals** (design decision, from the 2023 blog post "mutable"): `mutable squareArea = length * length` would keep recomputing when `length` changes, while `constant` stays the first value. Today a `mutable` only changes when it is reassigned (README). Within one method the compiler could recompute the dependent mutables after each reassignment of their inputs; members would need dependency tracking across methods.
