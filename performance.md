## Memory model change (design, 2026-11-26; steps are tried in this order, a step stays only when it is safe and gains about 3 %; step 1, lane recycling in pool jobs, landed: `strict_rc_dead_job` in `NativeRuntime.mlir`, `Examples/ParallelRecycled.strict`)
What exists (read from `NativeRuntime.mlir` and `ParticleStress.mlir`, baseline 8.7-10.5 ms per tick at 45 % machine load, minimum of 3):
- A value is one f64 word, an object lives in a 64 KB page of its size class (mark byte, i32 count, i16 flags per object) or in a large block. The count is the number of heap slots referencing the object, stack slots and registers are never counted. An object is freed by its count when (a) a reclaim finds count 0 and its conservative stack scan finds no reference, or (b) the compiler proved the dying local was the only holder (`MlirOwned`, `MlirSpent`, `MlirDying` emit `strict_rc_dead` and `strict_rc_unshared`): then count 0, not pinned, not free is enough.
- Inside a pool job nothing is counted: a store pins its target (flag 32) and a pinned object is only freed by the collector. Every lane (thread) allocates from its own spans, pages it takes in a job are tagged with job and lane (`strict_gc_mine`).
- The new Particle is already built in place: the collecting loop reserves a list with one inline block per element (`strict_record_list_new`), `strict_struct_destine_block` hands the block to `Particle.Advanced`. What `Particle.Advanced` still allocates per particle is the 16 byte `Lifetime` of `lifetime.Advanced(seconds)` (the Error branch keeps it from being split into registers), 16 MB of dead blocks per tick that wait for a young collection.

Step 2, ownership passing. A call site passes ownership of an argument when the caller's local is spent by the call (`MlirSpent`: last load, or reassigned from this call's result as in `current = current.Advanced(Tick)`) and the value is owned by the local (`MlirOwned`). The callee gets an owning variant where `value` is an owned local: `Type(value, member = x)` rebuilds the block in place when `strict_rc_unshared(value)` holds at runtime (members not named keep their counts, replaced ones go through `strict_rc_put`), and a member replaced by a call on that member's owner (`EffectSystem(system, particles = system.Living(seconds))`) moves out: `Living` may write its result into the old list when the list's count is 1 (only `system` holds it) and `system` is unshared. The loop then is an in-place filter and map: each chunk writes at or below the index it reads, element blocks are the old elements' blocks, holes are closed as today. Use after free is ruled out twice: statically (no load of the caller's local after the call; the owning variant copies as soon as `value` or the moved member flows anywhere but member reads and the rebuilt result) and dynamically (the unshared test sees every heap alias through the count and every job alias through the pin; a failed test copies). In-place writes happen after the last instruction that can return an Error, so a failed call leaves the old value whole (the rule destined structs already follow).

Step 3, 32 bit members. A type made only of numbers (directly or through such member types) gets a layout table (offset and width per member): members constrained with `value.Bits is 32` take 4 bytes, others 8. Its blocks are leaves (allocation kind 32, never scanned), so two floats in one word are never read as a reference by the collector or by `strict_rc_release`. Construction already rounds with `strict_single`, reads widen exactly, so results do not change. Every reader of member slots goes through the layout: FieldLoad, unpacking of `value`, the inline blocks of record lists (slot bytes instead of slot count), equality, `to Text`, `strict_records_flat` for GPU loops. Types with any reference member keep 8 byte words.

Step 4, incremental marking for framed programs (`strict_frame_ended`). A full collection becomes a cycle: start (roots pushed, a few 100 us), slices at frame ends that drain the mark stack for a time budget (1 ms), finish (stacks and dirty cards scanned again until the stack is empty, then the lazy sweep that exists). Invariant: a marked object never holds an unmarked one without its card being dirty; all stores already mark their card (`strict_gc_written`, `strict_gc_card`, `strict_rc_put`), objects allocated during a cycle are born marked, stacks count as unscanned until the finish. A block freed by its count during a cycle loses its mark, a stale entry on the mark stack then scans cleared memory or a link (not a reference). No slice runs inside a pool job; a young collection due during a cycle finishes the cycle first (logged as one pause). Programs without frames keep the stop-the-world collection.

Tests for every step: stress types in `Compiler/` built natively and run on the VM (dying locals in parallel and serial loops, a value kept by a second local, by a list, by a nested loop's context and by a constant while its first holder dies; freeing the same value twice through two paths; lists growing while old versions are still read), each run also with `STRICT_RC_CHECK=1` (counts verified against a full marking, "would free a reachable object" reports), `STRICT_RC_DEAD=0` and `STRICT_RC=0` (same output), the two-stage fixpoint, `strict check .`, ParticleStress 1M (minimum tick time of 5 runs and the pauses of `STRICT_GC_LOG`).
