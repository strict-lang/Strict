## Collector

## Memory model change (design, 2026-11-26; step 1, lane recycling in pool jobs, landed: `strict_rc_dead_job` in `NativeRuntime.mlir`, `Examples/ParallelRecycled.strict`)
What exists (read from `NativeRuntime.mlir` and `ParticleStress.mlir`, baseline 8.7-10.5 ms per tick at 45 % machine load, minimum of 3):
- A value is one f64 word, an object lives in a 64 KB page of its size class (mark byte, i32 count, i16 flags per object) or in a large block. The count is the number of heap slots referencing the object, stack slots and registers are never counted. An object is freed by its count when (a) a reclaim finds count 0 and its conservative stack scan finds no reference, or (b) the compiler proved the dying local was the only holder (`MlirOwned`, `MlirSpent`, `MlirDying` emit `strict_rc_dead` and `strict_rc_unshared`): then count 0, not pinned, not free is enough.
- Inside a pool job nothing is counted: a store pins its target (flag 32) and a pinned object is only freed by the collector. Every lane (thread) allocates from its own spans, pages it takes in a job are tagged with job and lane (`strict_gc_mine`).
- The new Particle is already built in place: the collecting loop reserves a list with one inline block per element (`strict_record_list_new`), `strict_struct_destine_block` hands the block to `Particle.Advanced`. What `Particle.Advanced` still allocates per particle is the 16 byte `Lifetime` of `lifetime.Advanced(seconds)` (the Error branch keeps it from being split into registers), 16 MB of dead blocks per tick that wait for a young collection.

Step 2, ownership passing (refined 2026-11-26 after reading the emitters and the bytecode of `Advance`, `Advanced` and `Living`; owner item 74: build it). Three frames take part, each with a syntactic rule the compiler checks and a test the runtime makes; no new escape analysis is needed because every rule only admits the exact shape.
- Frame 1, `current = current.Advanced(Tick)` in a loop (hands the old struct): the local is loaded exactly once in the loop body, as the receiver of the call whose result is stored back into it; the call has no other argument of the struct's type; every other store to the local stores a parameter. Before the call the old block becomes the struct destination (`strict_struct_destine`, the existing channel) when it is not one of those parameters and `strict_rc_unshared` holds. The callee knows its receiver is given up when the destination it took is its own receiver.
- Frame 2, `EffectSystem(system, particles = system.Living(seconds))` (gives the member list): the receiver is a local whose stores are constructor results or results of calls on itself without another argument of its type; after the call the method only loads the local to read other members, builds the type from them and returns that; no register read after the call was loaded from the member before it. At run time the list is given (`strict_list_give`, a thread local the callee takes in its prologue) when the local's block is unshared, the list is not pinned or shared and its count is exactly its holders in this frame: the local's block, plus the receiver's block of this method when frame 1 gave it up and it still holds the same list.
- Frame 3, `for particles` in `Living` (writes in place): the member is loaded once in the method, by the loop; the loop collects records of the element type of the member; the call building the element has the loop's `value` as its receiver and `value` is not loaded after it. When the given list is the iterated one and it is a finished record list (large, items inside its own allocation), the result list is that list: no hole prefill, each iteration first replaces its item by a hole and destines the element's own block, a serial loop takes a fresh list instead. The record cache and the device copies of the list are forgotten.
Why no stale read is possible: heap references to the list or into its blocks are counted on its allocation, references written in pool jobs pin it, constants are pinned; stack references can only sit in the three frames (frames above frame 1 never saw a list made inside its loop, the first pass is not owned because the old value is the parameter), and the three rules leave no register or local in them that still reads the list or an element after the give. A failed loop leaves a half written list nobody can read: the Error returns through frames that gave it up.

Tests: stress types in `Compiler/` built natively and run on the VM (dying locals in parallel and serial loops, a value kept by a second local, by a list, by a nested loop's context and by a constant while its first holder dies; freeing the same value twice through two paths; lists growing while old versions are still read), each run also with `STRICT_RC_CHECK=1` (counts verified against a full marking, "would free a reachable object" reports), `STRICT_RC_DEAD=0` and `STRICT_RC=0` (same output), the two-stage fixpoint, `strict check .`, ParticleStress 1M (minimum tick time of 5 runs and the pauses of `STRICT_GC_LOG`).
